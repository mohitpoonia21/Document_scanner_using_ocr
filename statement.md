## 1. Problem Statement

Taking a photograph of a document is an easy way to digitize it, but the resulting image may not look like a proper scanned document. The page can be tilted, the background can be visible around the document, and uneven lighting can affect the quality of the image. These problems can also make text extraction less accurate.

The purpose of this project is to develop a simple document scanner that can detect a document from an image, correct its perspective, improve the scanned image, and extract the text from it using Optical Character Recognition (OCR).

---

## 2. Proposed Solution

The proposed system is a Python-based command-line application that combines Computer Vision techniques with OCR.

OpenCV is used for image processing and document detection, while EasyOCR is used to recognize text from the processed document.

The system is divided into three functional modules:

### Module 1 — Preprocessing and Document Detection

The first module prepares the input image for further processing. It validates the image, resizes it when required, detects edges, searches for a document-like contour, identifies the four document corners, and applies a perspective transformation.

The perspective transformation changes the tilted document into a more straight and scan-like view. The resulting image is then enhanced before it is passed to the OCR module.

### Module 2 — OCR Text Extraction

The second module is responsible for extracting text from the processed document using EasyOCR.

It stores the recognized text along with confidence values. A minimum confidence threshold can be supplied through the command line so that OCR results with low confidence can be filtered out.

### Module 3 — Export and Reporting

The third module handles the output generated by the application. It saves the processed scan and OCR information in different formats.

The supported outputs include:

- PNG scan image
- TXT text file
- JSON OCR data
- PDF file

The application also maintains a pipeline log to record important processing events.

## 3. Functional Requirements

### FR1 — Document Preprocessing and Detection

The system shall:

- Accept an image as input.
- Validate the image path and file type.
- Support common image formats.
- Resize images when necessary.
- Detect edges in the image.
- Search for a document-like boundary.
- Identify four document corner points.
- Order the detected points correctly.
- Apply perspective correction.
- Enhance the corrected document image.
- Report an error if a suitable document cannot be detected.

### FR2 — OCR Text Extraction

The system shall:

- Use EasyOCR to recognize text.
- Support configurable OCR languages.
- Allow a minimum confidence threshold to be specified.
- Filter OCR results using the confidence threshold.
- Store recognized text lines with their confidence values.
- Provide the combined extracted text.
- Calculate the average OCR confidence.
- Report an appropriate error when usable OCR text cannot be obtained.

### FR3 — Export and Reporting

The system shall:

- Save the processed document image.
- Save extracted text as a TXT file.
- Save OCR information as a JSON file.
- Generate a PDF containing the scan and extracted text.
- Create the required output directory when necessary.
- Maintain a pipeline log.

## 4. Non-Functional Requirements

### Performance

The application should process normal document images within a reasonable amount of time. The OCR reader should not be unnecessarily initialized repeatedly.

### Reliability

The system should handle expected problems such as invalid files, unsupported formats, missing documents, and OCR failures without producing an uncontrolled program crash.

### Usability

The command-line interface should provide clear arguments and useful messages showing the processing status and final result.

### Maintainability

The application is separated into different modules for preprocessing, OCR, exporting, utilities, logging, and command-line control. This makes individual parts easier to understand and modify.

### Error Handling

The system uses application-specific exceptions for expected problems such as invalid files, document detection failures, and OCR extraction failures.

### Logging

Important processing events are recorded in a pipeline log so that failures and successful operations can be checked later.

13. Limitations

The document detection process works best when the complete page is visible and there is a reasonable difference between the document and its background.

Detection may become less reliable when:

The document is partly outside the image.
The background contains complex patterns.
The document and background have similar appearance.
The photograph has strong distortion.
Lighting conditions are poor.

OCR accuracy can also depend on:

Image resolution
Lighting
Text size
Font
Language
Image quality
Selected confidence threshold

The current implementation is command-line based and does not include direct camera capture or a graphical user interface.

17. Conclusion

The Document Scanner Using OCR project demonstrates how basic Computer Vision techniques can be combined with OCR to process photographs of documents.

The preprocessing module handles document detection, perspective correction, and image enhancement. The OCR module provides text recognition and confidence filtering, while the export module saves the results in different formats.

The project also includes automated testing, error handling, logging, and design diagrams. The current implementation provides a foundation that can be extended later with a graphical interface, improved detection, and additional OCR features.
